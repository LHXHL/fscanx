### 方案（立项时必填）

- **做什么**：修 1 条（致远互联-OA 的 c 特征 `/yyoa/` 改 `/yyoa/ext/`）+ 摘 1 分支（SmartOA 删 `/smartoa/` 独立分支）+ 整删 2 条目（Log4j2、HIKVISION-视频监控）+ 清 1 死引用（Microsoft-HTTPAPI logic 的悬空 label b），收编上轮会话未立项的 7 处弱特征删除，重打包 gz。

- **怎么做**：致远 c 改 `/yyoa/ext/`——项目 6 个 seeyon poc 实证的老版目录结构，canonical 只回显被扫描的 `/yyoa/`，无法自证；SmartOA 摘分支（产品另有 3 个更强分支，零识别损失）；两条污染条目整删（294/80 条子规则、272/54 个随机 label、混入无关产品条件，无法验证保留子规则的产品相关性）；全库批量删除的止损边界用客观判据"特征路径 ∈ dirlist（扫描器自身会请求的 66 个路径）"划线——交集仅 2 项均已处置，低危 44 项（深路径/文件名特征，扫描器不会主动请求）保留记清单。

## BL-FP-005 favicon 图标抓取与哈希指纹识别（生产链路补齐）

- 模块：指纹库质量
- 优先级：P1
- 状态：已完成
- 价值：BL-FP-003 裁剪后 fingers 库的 519 条 hash 指纹（favicon md5/mmh3 为主）在生产扫描中端到端生效——当前扫描器从不抓取网站图标，哈希表已在内存但永远无人调用。
- 关联模块文档：docs/modules/05-指纹库质量模块.md
- 关联计划：plans/2026-11-15-BL-FP-005-favicon抓取.md
- 关联代码：Plugins/faviconScan.go
- 验收状态：已验收

### 方案（立项时必填）

- **做什么**：web 扫描链路新增站点级 favicon 探测——三层候选源（首页 HTML base64 内联 → link 声明路径 → /favicon.ico 兜底）抓取图标字节，算 md5+mmh3 查 FaviconEngine 哈希表，命中指纹分词去重后合并进链尾 Product 行；新增 `-nofavicon` 参数（默认开启）可整体关闭。
- **为什么**：引擎层 FaviconEngine 数据已就绪（NewEngine 无条件初始化、Compile 从 fingers 填充哈希表），但生产链路零调用（MatchFavicon 仅测试与示例调用）；用户即将批量添加 favicon md5 指纹，前提是扫描器能把它们用起来。
- **怎么做**：纯 Plugins 层改动（mylib/finger 零改动）。新建 Plugins/faviconScan.go 承载探测全链路（HTML link 解析复用 x/net/html Tokenizer；请求复用 lib.Client 连接池；每站点最多 2 个额外请求、64KB 字节上限、拿到即停）；webScanTask.go 的 DoWebScan 产出行从"内部即时输出"改为"三段拆分存 scanPresents、由调用方控制输出时机"——中间行（还有跳转）即时输出，链尾行 favicon 探测合并后输出；common 加 NoFavicon 参数；顺带清理 scanType 2 死代码（注释占位 + 永不进入的死分支）。
- **为什么这么做**：favicon 定位为增强信息——任何失败静默放弃、关闭时零开销、失败站点输出与现状逐字节一致（回归底线）；哈希查表 O(1) 且 404 错误页哈希不在表内，天然无误报，无需魔数校验；中间行是跳转源页面指纹、不合并 favicon，仅链尾行代表站点最终形态。

### 范围

- favicon 探测全链路：HTML 解析（零 IO）→ 候选请求（最多 2 个）→ 哈希匹配 → 合并进链尾 Product 行
- `-nofavicon` 参数（默认 false = 探测开启，反向开关与 -np/-no 同模式）
- scanType 2 死代码清理

### 不做

- 不动 mylib/finger 引擎代码（FaviconEngine/MatchFavicon 现状可用）
- favicon 指纹不参与目录扫描差集判定（presentKey 不动——差集语义是目录页 vs 首页文本指纹，favicon 是站点级信息）
- 不收 og:image / manifest.json icons / HTTP Link 头（非标准 favicon 源，不值请求预算）
- goby 引擎不加 favicon 哈希能力（goby 规则格式 label/feature/is_equal 无哈希字段，哈希指纹按 BL-FP-003 决策归 fingers_http.json）
