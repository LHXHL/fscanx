### 方案（立项时必填）

- **做什么**：从 fingers_http.json 删除六类高危误报指纹（60 条整删）+ 2 条混合指纹删危险特征值，重打包 embed 用的 gz。
- **为什么**：fingers 引擎无 AND 逻辑（与 goby 的布尔表达式、ehole/fingerprinthub 的数组内 AND 形成对比），单一弱特征即命中。实测存在 body 含 "everything"/"web user login" 就报产品、body 含 "huawei"/"金山" 就报华为/金山设备、`juniper` 一词同时报两个不同产品等误报模式。

## BL-FP-002 纯 Go 指纹重打包工具（替代 gzip 命令）

- 模块：指纹库质量
- 优先级：P1
- 状态：已完成
- 价值：消除指纹维护对 gzip 命令的依赖（Windows 无内置 gzip），"改明文 → go run 打包 → go build"全链路纯 Go 跨平台。
- 关联模块文档：docs/modules/05-指纹库质量模块.md
- 关联计划：—
- 关联代码：mylib/finger/cmd/pack/main.go

### 方案（立项时必填）

- **做什么**：新增 `mylib/finger/cmd/pack` 工具，把 resources 下的指纹明文 JSON 重打包为 embed 用的根目录 .gz（fingers_http 与 goby 两对）。
- **为什么**：原工作流（resources/cmd.txt）依赖 `gzip -c` 外部命令，Windows 无内置 gzip，维护者改指纹后重打包受阻（README.md:156 亦如此指引）。
- **怎么做**：`compress/gzip` 标准库实现；json.Valid 前置校验防打包坏 JSON；mtime=0 + BestCompression 确定性输出（内容不变则 gz 字节不变，git diff 友好）；从项目根目录 `go run ./mylib/finger/cmd/pack` 调用。
- **为什么这么做**：go build 无原生打包钩子（go:generate 需显式执行、-toolexec 需每次传 flag），用户选定保留 gz 体积优势 + 显式打包脚本方案；目录内历史 gz 副本无代码引用，脚本只维护根目录 embed 真源。

### 范围

- 新工具打包两对文件：`fingers_http.json/fingers_http.json` → `fingers_http.json.gz`、`goby.json/goby.json` → `goby.json.gz`
- 同步维护文档：README 工作流说明、resources/cmd.txt、模块文档 05

- 不做打包后自动触发 go build（保持单职责，用户自行串联）

## BL-FP-003 指纹库裁剪为 hash-only（删除全部文本特征指纹）

- 模块：指纹库质量
- 优先级：P0
- 状态：已完成
- 价值：彻底消灭 fingers 引擎文本特征误报——hash 类特征（favicon md5/mmh3、body 哈希）碰撞概率趋近于零，识别结果全部可信。
- 关联模块文档：docs/modules/05-指纹库质量模块.md
- 关联计划：—
- 关联代码：mylib/finger/resources/fingers_http.json/fingers_http.json
- 验收状态：待验收

### 方案（立项时必填）

- **做什么**：删除全部非 hash 指纹——无任何 hash 特征的 3770 条整删；124 条混合指纹（favicon+文本）修剪文本特征只留 hash 部分。4289 → 519。
- **为什么**：BL-FP-001 首轮清理后用户实测误报仍偏高；fingers 引擎纯 OR 短路语义下任何文本特征（body/header/regexp/cert）都是独立误报源，hash 是唯一零误报特征类型。用户拍板"把非 hash 类型的指纹全部删除"。
- **怎么做**：Python 脚本按"含 regexps.md5/mmh3 或 rule.favicon.md5/mmh3"判定保留；混合指纹的 regexps 文本字段（body/header/regexp/cert/vuln/version）全部移除，regexps 清空则删键（与纯 hash 指纹形态一致）；cmd/pack 重打包 + validate + go build。
- **为什么这么做**：混合指纹延续 BL-FP-001"删特征保指纹"先例——文本特征是误报源，hash 特征仍提供真阳性；识别覆盖损失由 goby 引擎的文本指纹兜底（fscanx 加载 fingers+goby 双引擎）。

### 范围

- fingers_http.json 裁剪至 519 条（395 纯 hash + 124 修剪后混合）
