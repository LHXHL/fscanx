### 方案（立项时必填）

- **做什么**：修 1 条（致远互联-OA 的 c 特征 `/yyoa/` 改 `/yyoa/ext/`）+ 摘 1 分支（SmartOA 删 `/smartoa/` 独立分支）+ 整删 2 条目（Log4j2、HIKVISION-视频监控）+ 清 1 死引用（Microsoft-HTTPAPI logic 的悬空 label b），收编上轮会话未立项的 7 处弱特征删除，重打包 gz。
- **为什么**：用户实测 https://120.77.222.29/yyoa/（nginx+PHP 软404站，页面模板回显请求路径）恒报"致远互联-OA"。根因：goby 原始规则的 path/status_code 探测上下文在数据转换时被剥离，"路径存在性探测"退化为"全响应子串匹配"（`goby.go:105`），页面 `<link rel='canonical' href='.../yyoa/'>` 回显请求路径使特征 c 自证，d（is_equal=false 排除采集占位页）在正常页面恒真，c&&d 误报。误报同时被 Log4j2 污染条目放大（其 294 条子规则混入了 yyoa 条件，任一命中即报 Log4j2）。
- **怎么做**：致远 c 改 `/yyoa/ext/`——项目 6 个 seeyon poc 实证的老版目录结构，canonical 只回显被扫描的 `/yyoa/`，无法自证；SmartOA 摘分支（产品另有 3 个更强分支，零识别损失）；两条污染条目整删（294/80 条子规则、272/54 个随机 label、混入无关产品条件，无法验证保留子规则的产品相关性）；全库批量删除的止损边界用客观判据"特征路径 ∈ dirlist（扫描器自身会请求的 66 个路径）"划线——交集仅 2 项均已处置，低危 44 项（深路径/文件名特征，扫描器不会主动请求）保留记清单。
- **为什么这么做**：改特异特征优先于删分支（保识别能力、误报消除等价）；污染条目整删优先于手术修剪（修剪需重建 2231 字符 logic，且混入规则的归属无法考证）；批量修只动"扫描器自身可触发"的项，避免对 44 个真特征误伤。is_equal=false 取反语义经数据抽样证实与 goby 原库一致（排除条件用法普遍），引擎代码不改。
