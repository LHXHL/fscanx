### 方案（立项时必填）

- **做什么**：修复 5 个构建失败包（10 处）+ 4 个测试文件编译失败（engine_test.go ×2、gonmap_test.go ×1、cssp_test.go ×1）+ 对 11 个依赖被裁数据的测试做数据可用性适配（skip）。
- **为什么**：974150e/bd7e479 同系列"内存优化"重构（git 溯源亲证：失败文件最后修改均停在这两个提交）裁剪了 wappalyzer/nmap 数据 embed（`resources/embed.go` 三处 `////go:embed` 注释）并改了 API/结构体，下游没跟上——cmd 三工具用 `fingers.NewEngine` 缺 import（根包 package 名 fingers，路径 `mylib/finger`）；examples 用上游旧 API `wappalyzer.New()`（现名 `NewWappalyzeEngine`）；rdpgfx 的 `gfxClient` 字段 `w` 被删而引用它的方法残留；engine_test 两处按旧签名传 int（现 `portStr string`）；gonmap_test 引用已删除的 `scanner.ScanTimeout`（现 API `Scan(ip, portStr, level, sender)`）；cssp_test 给 `EncodeDERTRequest` 传 `""` 应为 `[]byte`。`NewEngine` 对单引擎初始化失败是整体报错，且默认引擎集含 wappalyzer/nmap，故凡裸 `NewEngine()` 或构造被裁引擎的测试（11 个）必然 panic/t.Error。
- **怎么做**：①三个 cmd 文件补 `import "github.com/killmonday/fscanx/mylib/finger"`；②examples `New()`→`NewWappalyzeEngine()`（`Fingerprint`/`FingerprintWithCats` 签名已核对兼容）；③gfxClient 补回字段 `w core.ChannelSender`（接口含 `SendToChannel`，core/types.go:23）；④engine_test `80`→`"80"`、`port`→`strconv.Itoa(port)`（补 strconv import）；⑤cssp_test `""`→`[]byte("")`；⑥gonmap_test 按新 `Scan` 签名适配或随数据裁剪 skip（执行时按实际依赖定）；⑦11 个受裁剪测试（finger 根包 TestEngine/TestEngine_Match/TestFavicon/TestEngine_MatchWithEngines/TestAlias/TestEngine_Wappalyzer/TestNmapEngine/TestServiceEngine + wappalyzer 包 TestCookiesDetect/TestHeadersDetect/TestBodyDetect）开头判 `len(resources.XxxData)==0` 即 `t.Skip`（注明数据裁剪原因）。
- **为什么这么做**：编译修复全部零行为影响——缺 import/缺字段/旧 API 名/旧签名是重构遗漏的铁证，补齐即恢复编译；测试用数据判据 skip 而非恢复 embed——数据裁剪是既定设计（主程序 `use_engine` 仅 fingers+goby），恢复 1.2MB 嵌入违背内存优化意图；`len(...)==0` 判据在数据恢复嵌入时自动失效恢复真跑，自愈。grdp 既有 6 包 vet 分析器告警（ber/rfb/rle/gcc/pdu/login，非编译错误、与本次重构无关）明确范围外。
