# POC 扫描模块 Backlog

POC 扫描模块：修复并重构 Web POC 检测的触发与加载机制。起点是 2026-11-15 用户双反馈——"-poc 实际没有发 poc 请求（PocName 为空）"与"设置 -poc 不指定 -pocname 不会发送 poc 扫描"；只读审计证实触发链两处断裂：空 `-pocname` 走全项目零填充的 `HostInfo.PocName` 死字段空循环，`-m webpoc` 非 URL 目标空 Url 越界 panic 被 recover 吞掉，两者都表现为静默零请求。本模块四步走：止血（触发修复）→ 合并式加载（新增 poc 零编译）→ 指纹定向管道（流量从 386 poc×每 URL 降到按指纹命中定向）→ 独立 web 维护端（用户零手写 yaml）。定位小而精，放弃 nuclei 兼容。

002~008 六轮持续打磨：合并式加载与绑定关系外置落地后，指纹定向管道接入（实测流量 612→8 条，98.7% 降幅）；fscanx-web 独立维护端从原生单页重做为 vue-element-plus-admin，历经绑定页交互重构、binds SQLite 化（墓碑机制）、指纹结构化 CRUD、登录认证、内置 POC 写回编辑，形成"POC 管理 / 绑定关系 / 指纹库"三页面维护体系。2026-11-17 五问调研（重复打击/去重/path/并发/目录扫描联动）暴露绑定键名空间脱节（出厂英文旧名 vs 引擎输出标准名）与执行层串行问题，立项产品册改造（出厂两文件合并 + 三视角维护端）与并发口径两项。

2026-11-17 BL-POC-009 产品册全层落地：出厂 aliases.yaml+binds-seed.yaml 合并重刷为 catalog.yaml（50 条目，weaver 拆三子产品，中文名产品出厂绑定从死变活）；扫描器侧外置 catalog.yaml 双注入（别名进归一表+pocs 进绑定合并）+ 绑定名单精确索引；web 端三视角维护（标准产品页/指纹页归属判定/POC 页绑定弹窗）+ 存量迁移，绑定关系页退役。全量验收实测后置待验收。
