# fscanx-web 部署运行手册

fscanx-web 是 fscanx 的本地维护端：一个独立二进制，提供网页界面维护 POC、指纹与"指纹→POC 绑定关系"，不用手写 yaml/CEL。它与扫描器 `fscanx` 是两个独立程序——web 端负责"改数据"，扫描器负责"跑扫描"，两边通过部署目录里的文件衔接。

## 一、从源码构建

环境要求：Go ≥ 1.20；Node.js + pnpm（仅构建前端用）。

**构建顺序是铁律：必须先构建前端，再编译 Go。** 前端产物经 `go:embed` 打进二进制——先 `go build` 会把旧产物（或空产物）嵌进去，表现为白屏或行为回退，且编译能通过、不易察觉。

```bash
# 1. 构建前端（首次会自动 pnpm install），产物同步到 cmd/fscanx-web/static/
bash web/build.sh

# 2. 编译 fscanx-web 二进制（产物在仓库根）
go build ./cmd/fscanx-web
```

> 仓库不再提交前端构建产物（`static/assets/` 已忽略），所以新 clone 后**必须**先跑 `web/build.sh`，跳过直接 `go build` 得到的二进制没有可用前端。

只改了 Go 代码（不动前端）时，可跳过第 1 步直接 `go build`。扫描器 `fscanx` 本体照常 `go build .`，与 web 端互不影响。

## 二、部署目录与启动

推荐部署形态：**fscanx.exe 与 fscanx-web.exe 放同一目录**（两者通过同目录文件联动），该目录即"扫描器部署目录"。

```
部署目录/
├── fscanx.exe        # 扫描器
├── fscanx-web.exe    # 维护端
├── binds.db          # 绑定关系主存储（首次使用 web 端编辑时自动创建）
├── binds.yaml        # 绑定关系文件快照（web 端自动重生成，也可手改）
└── pocs/             # 外置 POC 目录（可选，web 端建的 POC 落在这里）
```

启动：

```bash
# Windows（仓库根做仓库根参数，供指纹编辑/重打包读写源文件用）
fscanx-web.exe -addr 127.0.0.1:7758 -root E:\path\to\fscanx-repo
```

| 参数 | 默认 | 说明 |
|------|------|------|
| `-addr` | `127.0.0.1:7758` | 监听地址。只在本机用保持默认；如需内网其他机器访问改成 `0.0.0.0:7758`（见安全边界） |
| `-root` | `.` | fscanx 仓库根（含 `mylib/`），**指纹编辑与重打包功能**读写这里的源文件；poc/binds 与此参数无关，固定读写二进制旁 |

启动横幅会打印访问地址与默认账号。

## 三、登录

- 默认账号：**admin / admin123**（启动横幅也会打印）。
- 登录签发的会话 token 保存在服务端内存里：**重启 fscanx-web 后所有登录失效**，浏览器会自动跳回登录页，重新登录即可，属正常行为。
- 退出：右上角头像下拉 → 退出系统。
- 改密码：修改 `cmd/fscanx-web/auth.go` 顶部的 `authUsername` / `authPassword` 常量后重新编译。本地单用户工具，不做密码存储与找回。

## 四、绑定关系的数据模型（手改文件前必读）

绑定关系有两份存储，分工明确：

- **binds.db（SQLite）**：web 页面编辑的**主存储**。页面上增删改都先写它。
- **binds.yaml**：扫描器实际消费的文件快照。web 端每次增删改后**自动整份重生成**；同时它也是手改入口。

同步语义（自动处理，无需人工干预）：

| 你做的事 | 系统行为 |
|---------|---------|
| 在网页上增删改绑定 | 写 binds.db → 自动重生成 binds.yaml |
| 用文本编辑器手改 binds.yaml | 下次任何读写时自动检测（哈希比对）并吸收进 binds.db |
| 删掉 binds.yaml | 按 binds.db 现状重新生成（不会丢数据） |
| 把 binds.yaml 清成空文件 | 视为显式清空外置绑定（区分于误删文件） |
| binds.yaml 内容写坏了 | 接口显式报错提示修复，不会静默吞掉你的手改 |

两个手改注意事项：

1. **不要删 `pocs: []` 的条目**——这是"墓碑"，表示该产品的内置种子绑定已被你在网页上删除。引擎按"同名覆盖"语义消费它；删了墓碑，已删除的内置绑定会悄悄复活。
2. 同一产品只会有一条绑定记录（主键约束），同名重复行按后者覆盖前者吸收。

## 五、典型使用流程

**改绑定 → 扫描生效**：绑定关系页（或 POC 页的"绑定产品"弹窗）编辑并保存 → **重新跑一次 fscanx 扫描**即生效（扫描器启动时读 binds.yaml；常驻中的扫描进程不会热加载）。

**新建 POC**：POC 管理页表单新建 → 落盘到二进制旁 `pocs/` → fscanx 零参数自动加载，无需编译。

**改指纹**：指纹库页编辑明文 JSON → 点重打包（产物 `.gz` 与命令行 `go run ./mylib/finger/cmd/pack` 字节一致）→ **重新编译 fscanx** 后生效（指纹保持编译嵌入，不做运行时外挂——设计决策见模块文档）。

## 六、开发模式（改前端时用）

```bash
cd web && pnpm dev:admin   # vite :4000，/api 代理到 127.0.0.1:7758 的 fscanx-web
```

改完仍要以"构建产物版"终验（dev 模式从磁盘服务文件、不经过 embed，是验证盲区）。

## 七、安全边界（本地工具语义，使用前知悉）

- HTTP 明文传输（含登录密码），无 HTTPS——适合本机或可信内网；不要把端口暴露到不可信网络。
- 无防爆破限速、单账号无角色体系——本地单用户定位，认证门的作用是"端口不再裸奔"，不是对抗定向攻击。
- 所有 `/api/*` 写接口需登录（Authorization token），登录端点与静态资源除外。

## 八、故障排查

| 现象 | 原因与处理 |
|------|-----------|
| 访问白屏 | 二进制里嵌的前端产物缺失/陈旧——按"一、从源码构建"顺序重来（前端先行） |
| 登录后一点就跳回登录页 | 服务端重启过（token 全失效），重新登录即可 |
| 明明改了绑定，扫描器行为没变 | 扫描器在启动时读 binds.yaml——重跑一次 fscanx |
| 7758 端口起不来 / 页面行为不对 | 旧的 fscanx-web 进程还占着端口，`taskkill /IM fscanx-web.exe /F` 后再启动 |
| 绑定页提示"binds.yaml 解析失败" | 手改的 yaml 写坏了，按报错修正文件或删掉它（会按 DB 重生成） |
| 指纹改了不生效 | 指纹是编译嵌入的：编辑 → 重打包 → **重新编译 fscanx** 三步缺一不可 |
