# 指纹库质量模块

## 模块定位

治理 fingers 与 goby 两个引擎指纹库（`mylib/finger/resources/` 下 `fingers_http.json` 与 `goby.json`，embed 入对应 `.gz`）的数据质量。

fingers 引擎为纯 OR 短路匹配（`mylib/finger/fingers/rules.go` `Rule.Match`：vuln→regexp→header→body→md5→mmh3 任一命中即返回 true），**无 AND 组合能力**——每条弱特征都是独立误报源；已裁剪为 hash-only（BL-FP-003），文本指纹职责移交 goby。

goby 引擎自带布尔表达式（`mylib/finger/goby/goby.go` 的 `logic` 字段，`&&`/`||` 顶层 OR 分支 + label 映射，is_equal=false 为排除语义"不含"），表达力强于 fingers，但其库有两类系统性误报源（BL-FP-004 治理，见下节判据）。对照：ehole/fingerprinthub 为数组内 AND（所有关键字必须全命中）。

## 关键功能怎么做

### 指纹库维护工作流

1. 编辑明文：`mylib/finger/resources/fingers_http.json/fingers_http.json`（4 空格缩进，键序 link/name/rule/tag[+focus 等]）
2. 重打包：项目根执行 `go run ./mylib/finger/cmd/pack`——纯 Go（compress/gzip 标准库）跨平台，内置 json.Valid 前置校验防打包坏 JSON，mtime=0 + BestCompression 确定性输出（内容不变则 gz 字节不变）；只写根目录 embed 真源，工作副本目录内的历史 gz 无代码引用不维护
3. 构建：`go build .`；需要格式校验时另跑 `go run ./mylib/finger/cmd/validate <路径> -engine fingers`

### 误报判定标准（BL-FP-001 首轮，2026-11-14）

"极可能误报"的六类判据 + 补充类，整条删除仅适用于无强特征（md5/mmh3/regexp/vuln/cert/favicon）的指纹：

| 类别 | 判据 | 示例 |
|------|------|------|
| 通用功能短语 | body 出现即命中的功能描述词 | everything、web user login、web configurator、file upload manager |
| HTTP 标准头 | 标准协议头作 header 特征 | alt-svc、authenticate |
| 厂商名报具体产品 | body 只含厂商名/集团名 | huawei、Cisco、Juniper、金山、金蝶 |
| 同词撞车归属错误 | 一特征挂多个不同产品 | x-powered-cms→3 产品、juniper→2 硬件 |
| 冷门词典词 | 日常词义产品且极冷门 | guppy(孔雀鱼)、pothos(绿萝)、cougar |
| 知名产品词典词 | 产品名本身是常用词 | harbor、zeppelin、express、tapestry |
| 2 字中文公司名 | body 仅 2 字中文 | 凡科、捷普、泽元、青果 |

混合指纹（强特征+危险弱特征并存）只删弱特征值、保留指纹——弱特征是误报源，强特征仍提供真阳性。

### 非误报的已知数据问题（不在误报清理范围）

- 359 组大小写/分隔符重复指纹（`Apollo`/`apollo` 等）——冗余输出非误报
- 同产品多名撞车（dreambox 两签、zfsoft/正方教务）——归属相同仅名称冗余

### favicon 图标抓取与哈希指纹识别（BL-FP-005，2026-11-15）

fingers 库的 hash 指纹（favicon md5/mmh3）此前只有引擎没有链路——FaviconEngine 哈希表由 `NewEngine` 无条件加载，但扫描器从不抓取图标，519 条哈希指纹全部闲置。本功能补齐生产链路（纯 Plugins 层，`Plugins/faviconScan.go`）：

1. **候选解析（零 IO）**：DoWebScan 拿到首页 body 时顺手用 x/net/html Tokenizer 解析 `<link>` 候选——rel 含 icon token（shortcut icon/alternate icon 经 token 命中覆盖）为主、apple-touch-icon 等为次、`<base href>` 为相对基准、data URI 内联图标（须声明图标 rel）解码字节优先；候选随 `scanPresents` 携带
2. **三层探测（预算 2 请求、64KB 上限、拿到即停）**：内联（零请求）→ link 声明路径（站点自声明优先，浏览器语义）→ `/favicon.ico` 兜底；走 `lib.Client`（与 DoWebScan 同策略短连接 Connection: close，跟随重定向 Go 默认上限 10 跳）
3. **匹配与合并**：图标字节算 md5+mmh3 查 FaviconEngine 表，经 MergeFrameworks alias 归并，命中指纹分词去重后合并进**链尾** Product 行（行三段拆分 prefix/products/suffix，中间行即时输出不受影响）；`-nofavicon` 整体关闭（默认开启）

失败语义：favicon 是增强信息，任何失败（404/超时/解码失败）静默放弃，关闭/失败/未命中时输出与无此功能逐字节一致。

### goby 库误报判据（BL-FP-004，2026-11-14）

goby 引擎把所有 feature 当"全响应（状态行+头+体）小写子串"匹配（`goby.go` `GobyFinger.Match`），原始 goby 规则的 method/path/status_code 探测上下文在数据转换时已剥离。三类判据：

| 类别 | 判据 | 触发案例与处置 |
|------|------|----------------|
| 回显自证（高危） | 唯一正条件是短路径形 feature，且该路径 ∈ dirlist（扫描器自身会请求） | 致远互联-OA `/yyoa/`：扫描 /yyoa/ 被 PHP 软404页 canonical 标签回显进 body，c 自证 + d（排除"采集占位页"）恒真 → 误报。处置：c 改 `/yyoa/ext/` 特异目录；SmartOA `/smartoa/` 无排除条件配合 → 摘分支 |
| 回显自证（低危） | 同上但路径 ∉ dirlist（深路径/文件名形） | 44 项保留——扫描器不主动请求，用户手动扫深路径概率低（Adobe-ColdFusion /cfajax/、Huawei-FusionCompute /OmsPortal/ 等，清单见 BL-FP-004） |
| mega-OR 污染条目 | 规则数异常多（>40）且混入与产品无关的其他产品特征 | Log4j2（294 规则混入 yyoa/NSX/JBoss/ReeCam 条件）、HIKVISION-视频监控（80 规则）——数据合并事故，任一子条件命中即报该产品。处置：整删（重建需原始干净数据源）。注意区分：UniView/Exim/dahua 规则数也多但是**同产品**多源合并（随机 4 字符 label 重命名），非污染不动 |

同产品合并条目内的通用弱词（UniView 'snmp'、Exim '220-'/'214-'、dahua 'jquery.ui.widget.js'/'rtsp' 等）属词典弱特征类，与 fingers 六类判据同源，留后续治理。

## 设计决策

- **为什么删指纹而不是给引擎加 AND**：数据层清理是零代码风险的最小变更；引擎加 AND 是架构演进（可参考 goby 的 `chainreactors/words/logic` 方案），收益与成本另评估。
- **为什么混合指纹只删特征值**：fingers 的 OR 语义下，强特征（favicon 哈希/md5）与弱特征独立命中；删整条会损失强特征的真阳性，删弱特征值即消除误报源。
- **hash-only 策略（BL-FP-003，2026-11-14 用户拍板）**：首轮清理后误报仍偏高，fingers 库整体裁剪为只含 hash 特征（4289→519）——文本特征（body/header/regexp/cert）在 OR 短路语义下都是独立误报源，hash 碰撞概率趋近零。**此后 fingers_http.json 只接受 hash 类指纹**（favicon md5/mmh3 为主），文本指纹需求由 goby 引擎承担（其 logic 布尔表达式支持 AND 组合，表达力更强）。
- **favicon 探测的关键取舍（BL-FP-005，2026-11-15 用户拍板）**：候选顺序 link 声明优先（站点自声明图标与哈希库收录对象一致，浏览器语义）而非标准路径最快；指纹合并进链尾 Product 行（否决独立行——输出碎片化）而非中间行；全部存活 web 端口无条件触发（新哈希指纹利用率优先，代价 +2 请求/站点）；预算按"请求次数"计——重定向链经 lib.Client 自动跟随，最坏 wire 请求数可超 2（client 整体 Timeout 兜底，接受该语义偏差）；哈希查表 O(1) 且 404 错误页哈希不在表内，天然无误报，不做图标魔数校验。
- **goby 批量删除的止损边界（BL-FP-004，2026-11-14 用户拍板）**：回显自证项只删"特征路径 ∈ dirlist"的高危项（扫描器自身可触发，客观判据），低危 44 项保留——避免对真特征误伤；污染条目整删而非手术修剪（修剪需重建 mega-OR 的 logic 且混入规则归属无法考证）。**改特异特征优先于删分支**（致远 c 改 /yyoa/ext/ 保老版识别可能，误报消除等价）。is_equal=false 取反语义经数据抽样证实与 goby 原库一致（排除条件用法普遍），引擎代码不改；恢复 path/status_code 主动探测属结构演进另行评估。
