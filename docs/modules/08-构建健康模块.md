# 构建健康模块

## 模块定位

维护仓库级构建与测试基线的健康：`go build ./...` 全量可编译、`go test ./...` 无因环境/裁剪导致的伪红。当前债务源为 974150e"内存优化"重构（数据 embed 裁剪 + API 变更）的下游未同步。

## 关键事实（2026-11-15 取证，独立审查复核）

- 主程序仅启用 fingers+goby 双引擎（`Plugins/webScanTask.go:40` `use_engine`），wappalyzer/nmap 引擎数据 embed 被 `resources/embed.go` 注释（`////go:embed` 三处）——**有意裁剪，非事故**。
- 该裁剪使 `NewEngine` 对 wappalyzer/nmap 必然报错（NewEngine 对单引擎初始化失败是整体返回错误，且默认引擎集 AllEngines 含两者），下游影响：cmd 示例工具构建失败（缺 import）、examples 旧 API、rdpgfx 残留方法、engine_test 旧签名、gonmap_test 已删 API、cssp_test 类型不匹配、11 个测试必红（裸 NewEngine 的 8 个 + wappalyzer 包 3 个）。
- 债务溯源：finger 域 6 文件停 974150e，rdpgfx.go 与 cssp_test.go 停 bd7e479（同系列"内存优化"重构）。
- grdp 另有 6 包 vet 分析器告警（ber/rfb/rle/gcc/pdu/login）——非编译错误、与重构无关，范围外既有状态。
- `noembed` build tag（`resources/noembed.go`）提供数据外部注入的替代形态。

## 关键决策

- **测试适配用数据判据 skip 而非恢复 embed（BL-BLD-001）**：数据裁剪是既定设计，恢复 1.2MB 嵌入违背内存优化意图；`len(resources.XxxData)==0` 判据在数据恢复嵌入时自动失效恢复真跑，自愈。
