# BL-POC-001 poc 触发修复

## 目标

`-poc` 开关恢复真实发包：修复空 `-pocname` 静默零请求与 `-m webpoc` 非 URL 输入路径越界 panic 两处触发链断裂。

## 问题（审计证据）

1. `PocScan/WebScan.go:26-33`：空 `-pocname` 走 `for _, pocStr := range info.PocName`——`HostInfo.PocName` 全项目零填充（唯一写点 scanner.go:401 透传空值），空 slice 循环 0 次，`Execute` 不可达，零请求。
2. `Plugins/webScanTask.go:251-254` webpoc 分支跳过唯一 Url 构造者 `WebScanWorker`；`WebScan.go:23-24` 对空 Url `strings.Split` 取 `buf[:3]` 越界 panic，被上游 recover 吞掉，零请求。
3. `WebScan.go:96` filterPoc `strings.Contains` 大小写敏感：`-pocname 74CMS` 匹配不到 `poc-yaml-74cms-sqli`。

## 方案

- `PocScan()`：删 else 死循环；`EqualFold(PocName, "all")` 置空归一（防 all 被当子串过滤）；统一 `Execute`——空=全量（`filterPoc("")` 现成语义）、名=过滤。空=全量为过渡语义，BL-POC-003 切换为指纹智能定向。
- `filterPoc`：双侧 `strings.ToLower` 比较。
- `webScanTask.go`：Url 构造段提取 `ensureURL(targetInfo)`（Url=="" 时按 80/443/协议探测构造）；`WebScanWorker` 与 webpoc 分支共用，webpoc 分支在 `PocScan.PocScan` 前调用。

## 风险

- `all` 若存在名字含 all 的 poc，归一化保证全量而非子集——已处理。
- 其他直达 `PocScan.PocScan` 的调用方：grep 证实仅 WebScanController 两处（webpoc 补构造后 Url 必非空；IsCheckPoc 路径 err==nil 隐含 WebScanWorker 已构造）。
- 死代码（`HostInfo.PocName`、`CheckInfoPoc`、`LoadMultiPoc`/`SelectPoc`）本 item 不动，归 BL-POC-003 统一退役（最小必要修改）。

## 验证方式

本地 python http.server 起目标 + 构建后实测四路径：
1. `-u http://127.0.0.1:PORT -m webpoc`（不带 -pocname）→ 目标日志有大量 poc 请求
2. `-h 127.0.0.1 -p PORT -m webpoc` → 不 panic 且发出请求
3. `-pocname 74CMS`（大写变体）→ 只发 74cms 系 poc
4. `-pocname all` → 全量（目标日志请求数与路径 1 同量级）
5. `go build ./...` + `go test ./PocScan/... ./Plugins/...`

## 验证结果（2026-11-15，全过）

| 路径 | 命令 | server 请求增量 |
|------|------|----------------|
| 空 -pocname | `-u http://127.0.0.1:18923 -m webpoc` | 1168 |
| IP 输入 webpoc | `-h 127.0.0.1 -m webpoc`（8080，Webport） | 1189 |
| 大写过滤 | `-pocname 74CMS` | 6（路径确为 74cms 系） |
| all | `-pocname all` | 1168 |
| 用户真实场景 | `-h 127.0.0.1 -p 18923 -m all -poc` | 1192 |

build+vet 通过；`go test ./PocScan/... ./Plugins/... ./common/` 全 ok。

## 执行中的意外发现（记入 item 状态记录）

1. `-m webpoc` 落 ParseScantype default 拿 PluginPortMap 调度键 1000003 当扫描端口（永远非法），webpoc 对 ip 输入从未工作过 → 补 `case "webpoc": PortsInput = Webport`（common/Parse.go，范围扩展）。
2. `-pa` 追加（ParseInput）先于 ParseScantype 模式端口覆盖执行，`-m <模式> + -pa` 追加会被覆盖 → fscan 系既有设计问题，未动。
3. 调试插曲：ensureURL 首版漏"Url 非空返回"守卫，把 -u 正确 Url 用 Ports 占位值重写 → 实测暴露后补守卫。教训：提取函数时外层条件必须随行。
