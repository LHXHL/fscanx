# plans/2026-11-16-BL-POC-008-内置POC写回编辑

# 目标

编辑内置 POC 时可选写回内置源目录（`<repoRoot>/PocScan/pocs/<embed 真实文件名>`，下次 go build 生效）；外置保存保留。同名内置/外置并存时按来源定位编辑，互不串写。

# 当前状态

- 立项完成（Mode B0 + 独立审查修订，用户批准 P1，连做 008→006）
- 现状事实：embed 经 `PocScan.WebScan.Pocs`（`//go:embed pocs`）；`listPocs` 合并视图不去重；`getPoc` 只收 name 外置优先；`putPoc` 一律写外置 `sanitizeName(name).yml`；`s.repoRoot` 来自 `-root`（默认 "."）
- 错误信封：`httpErrorf`（api_binds.go:175，200+{code:1,message}）——axios 对非 2xx 纯文本丢弃详情，写回拒绝提示必须走信封

# 执行计划

1. 后端 `api_poc.go`：
   - `pocItem` 加 `File`（内置=embed 真实文件名；外置=文件名）
   - `findPocFile(name, source)`：source=external 只查外置；source=built-in **仓库内置源文件优先**（最新源=下次编译内容，防写回后二次编辑踩 embed 陈旧基底）、embed 兜底；空 source 保持旧语义（外置优先）
   - `embedPocByName(name)`：embed 库按 name 找真实文件名（putPoc 写回目标的服务端解析——不信任客户端传路径）
   - `getPoc` 收 `source` 参数；`pocDetail` 加 `Source`/`File`
   - `putPoc` 加 `target`（built-in|external|空=external）：built-in 时 embed 库必须存在该 name（新建/改名写回拒绝）+ 目标文件必须已存在（防 -root 指错仓凭空造文件）；本函数错误面统一 httpErrorf 信封
2. 前端 `api/poc/index.ts` 类型与参数；`Poc.vue`：行点击传整行、保存目标 radio（仅内置来源行出现，默认内置源）、保存按钮文案随目标、内置目标提示行、删除外置对内置来源行禁用
3. 验证：go build/test；bash web/build.sh 产物版 headless 交互链；内置写回/拒绝/双行不串写/校验拦截实测

# 风险

- getPoc source=built-in 读仓库源文件偏离验收条件原文（原文"未重编译时 getPoc 返回内置内容不变"）——理由：写回后编辑器重载 embed 旧内容会以旧基底二次保存覆盖写回成果（跨刷新丢数据）；listPocs 保持 embed 真源不变。已记 item 状态记录，收尾汇报用户。
- -root 为相对路径 "." 时写回位置随 web 进程 cwd——与指纹明文同约定，不改。

# 验证方式

验收条件逐条（见 backlog item BL-POC-008），重点：写回后源文件更新+外置目录字节不变；root 指错/文件缺失拒绝提示；双行互不串写（双向字节验证）；坏 yaml/CEL 拦截且源文件不破坏。

# 决策记录

- 写回目标文件名服务端从 embed 库按（已校验一致的）yaml name 解析，不收客户端 SourceFile——消路径注入面
- 保存目标枚举沿用 pocItem.Source 既有词 built-in|external（审查 F1）
- getPoc built-in 读源文件优先（见风险①，防陈旧基底）
- putPoc 本函数错误面统一 httpErrorf（验收"提示明确"前提）
