## 执行计划

1. `common/config.go` + `common/flag.go`：`NoFavicon` 参数（`-nofavicon`，默认 false = 探测开启，反向开关，与 -np/-no 同模式）。
2. 新建 `Plugins/faviconScan.go`（每功能一文件）：
   - `extractIconCandidates(rawHTML, baseURL)`：Tokenizer 解析 link 标签（rel token 集合：icon/apple-touch-icon/mask-icon/fluid-icon；"shortcut icon"/"alternate icon" 经 token "icon" 覆盖；`<base href>` 基准；无 rel 但 href 以 .ico 结尾的 HTML4 老写法），输出按优先级排序的绝对 URL 候选 + data URI 内联解码字节。
   - `fetchIconBytes(u)`：lib.Client 请求，非 200 返回 nil，io.LimitReader 64KB，defer Close（与 DoWebScan 同策略短连接 Connection: close，非连接复用）。
   - `detectSiteFavicon(finalURL, hrefs, inline)`：三层调度——内联（零请求）→ hrefs[0]（站点自声明优先，浏览器语义）→ /favicon.ico 兜底；预算硬上限 2 请求，拿到即停。
   - `matchFaviconFrames(iconBytes)`：`Engine.MatchFavicon` + `MergeFrameworks` alias 归并。
   - `mergeFaviconLine(prefix, products, suffix, frames)`：分词去重（`Split(", ")` 精确比对）后重拼，兼容 products 为空时的 ", " 衔接。
3. `Plugins/webScanTask.go`：
   - `scanPresents` 增加 `linePrefix/lineProducts/lineSuffix`（行三段拆分，链尾可重拼）与 `iconHrefs/iconInline`。
   - `DoWebScan` 尾部行不再直接 LogSuccess，拆三段存 out；body 在手时顺手跑 extractIconCandidates（零 IO，tokenizer 微秒级）。
   - `WebScanWorker`：reurl 非空的中间行即时输出（跳转源页面不带 favicon）；reurl 为空的链尾行存 pending，链尾统一 favicon 探测合并后输出。
   - 清理 scanType 2 死代码（:420 注释占位、:586 `if scanType != 2` 死分支）。
4. `Plugins/favicon_test.go`：httptest 六类场景。

## 风险

- 链尾行延迟一拍（favicon 探测最多 2 请求 ≈ 2×WebTimeout 慢站点上限）；`-nofavicon` 无延迟。已接受。
- DoWebScan 输出契约从"内部即时输出"变为"返回行、调用方控制输出时机"——全仓库唯一调用方是 WebScanWorker，风险可控。
- `iconInline` 携带内联图标字节（几 KB~几十 KB），生命周期链尾一拍，WebScanRateCtrlCh 限并发，内存峰值可控。

## 决策记录

- 2026-11-15 用户拍板：①抓取顺序 link 声明优先、/favicon.ico 兜底（浏览器语义，站点自声明图标与哈希库收录对象一致）②指纹合并进链尾 Product 行（否决独立行方案——输出碎片化）③全部存活 web 端口无条件触发（新哈希指纹利用率优先）④新增 `-nofavicon` 反向开关默认开启（否决正向 bool——Go flag 正向开关默认 true 时关闭需 `-favicon=false`，用法别扭）。
- 关键设计：favicon 是增强信息，任何失败静默放弃；哈希查表 O(1)，404 错误页不会误报（错误页哈希不在表内），无需魔数校验。
- favicon 指纹不参与目录扫描差集判定（presentKey 不动）：差集语义是"目录页 vs 首页"文本指纹，favicon 是站点级信息与目录无关。
- 不收 og:image / manifest.json icons / HTTP Link 头（非标准 favicon 源，不值预算）。
