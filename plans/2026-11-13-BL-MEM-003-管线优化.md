## 风险

- mmap 路径在 Windows 开发机上无法直接运行验证——用 GOOS=linux go build 交叉编译验证编译期正确性，运行时行为依赖 Linux 环境真机验收（记入状态记录，不伪造验证）。
- 删除注释块用精确文本匹配，块边界以 Read 输出为准；多块删除从文件后段往前删避免行号漂移干扰人工核对。
- fl.Sync() 删除后断电可能丢尾部已写行——item 已记录该取舍（进程终止不丢：write(2) 完成=内核持有）。

## 验证方式

- `go build ./...`（Windows 本机）+ `GOOS=linux GOARCH=amd64 go build ./...`
- `go vet ./Plugins/ ./common/`
- `go test -race ./Plugins/ ./common/`
- qqwry 单测：仓库根运行（qqwry.dat 在根目录）
- 输出一致性：删除的均为注释/死代码/IO 层优化，不触任何格式化路径；WriteFile 的字符串拼接逻辑不动

## 决策记录

- 撤销 bufio（第三轮再审）：write(2) 直写已满足中断不丢，bufio 是负优化。
- loadIPDBFile 收 *os.File 而非 path：mmap 需要 fd；Stat 取长度。
- unix mmap 不做 Munmap：库常驻进程生命周期，OS 回收。
- CheckFile 失败仍 log.Fatalln（既有行为，不在本 item 范围，不动）。
