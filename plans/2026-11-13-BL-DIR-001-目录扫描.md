# BL-DIR-001 指纹导向目录扫描

- 日期：2026-11-13
- 关联 item：docs/backlog/04-目录扫描.md#BL-DIR-001
- 关联模块文档：docs/modules/04-目录扫描模块.md

## 目标

`-dir` 开启后，每个经 WebScanWorker 确认存活的站点由轮询环调度器逐路径探测内置字典（`-dirf` 覆盖），单站点在途 ≤1、多站点交错；命中（指纹非空且呈现二元组与首页不同）聚合到站点级，扫完输出同构 `[+] Product` 行后释放聚合器。默认关闭时行为与现状完全一致。

## 当前状态

- 方案三轮对抗审查定稿；Mode D 进入前修正一处表述矛盾：**判定与输出解耦**（判定用（指纹,标题）二元组，输出带完整指纹——原"只打差集"在 WordPress 后台场景输出空指纹）。
- 呈现 key 的指纹部分必须排序后拼接（指纹引擎输出顺序非确定为 pre-existing，MEM-003 实证）。

## 执行计划

1. 基础：dirlist.txt（path.txt 70 条拷入 Plugins/）、common -dir/-dirf flag
2. Plugins/dirscan.go：调度器（轮询环 + 在途门闩 + 阻塞等待唤醒 + Seal→Drain 两阶段停机）、worker 池 16、聚合器（呈现差集 + 站点内去重、url 取首个命中）、专用 client（CheckRedirect：先 host 后 path 前缀、限 3 次）
3. 接入：DoWebScan 加呈现返回值；WebScanWorker 收集全链呈现、成功后按 origUrl 注册；Scan/ScanFromReader 末尾 SealAndDrain
4. 单测（dirscan_test.go）：调度器交错/在途≤1/停机协议/panic 注入；httptest 判定矩阵（404、无指纹、呈现重合、同指纹新标题救回、302 三态）；-dirf 3 条 3 请求
5. 四层验证 + 文档同步（README -dir、设计总览 04 行去"未实施"、当前实现总览、04 模块文档、backlog/控制台/CHANGELOG）

## 关键实现决策（代码级）

- 呈现 key = `sort(fps) join "\x1f"` + `"\x00"` + title（title 空→"None" 与 DoWebScan 输出规范一致）
- DoWebScan 第三返回值 `[]string`（呈现 key，仅指纹非空时收集）；调用点全在 WebScanWorker
- 注册用进入 WebScanWorker 时保存的原始 URL（跳转改写 targetInfo.Url 前保存），目录路径基于它拼接
- LogWG 计数落聚合行粒度（LogSuccess 自带 Add/Done 配对），SealAndDrain 为同步屏障，语义等价且更简（相对 backlog 原"每任务 Add"表述，已记入状态记录）
- worker panic-safe：defer complete（在途--、唤醒、站点完成 flush）
- 调度器无可发射任务时 `<-wake` 阻塞等待（不持锁、不自旋）；complete/注册/Seal 均 wakeup
- 字典惰性加载 sync.Once；embed 失败/-dirf 错误记录后功能降级（不注册）
- CheckRedirect 返回 http.ErrUseLastResponse 拿最后响应（302 本身通常无指纹→自然丢弃）

## 风险

- LogWG/收尾时序：聚合行必须在 SealAndDrain 返回前全部 LogSuccess——complete 在锁外发送，done 关闭晚于最后一条聚合行 ✓（单测覆盖）
- 慢站点拖收尾（70×9s 最坏）——方案已记录为接受取舍
- fps 顺序非确定：排序后组 key 消除（不排序去重失效）

## 验证方式

- `go build .`（Win+Linux 交叉）、`go vet ./Plugins/ ./common/`、`go test -race ./Plugins/ ./common/`
- 验收矩阵 httptest 单测逐条对应 backlog 11 条验收
- 默认（无 -dir）零侵入：本地目标输出对比

## 决策记录

- 判定与输出解耦（见上）。
- Worker 池独立 goroutine（不用 PoolScan）：目录扫描生命周期跨越主流程各阶段收尾，与 pond 的 StopAndWait 顺序耦合风险高；固定 16 goroutine 生命周期清晰。
