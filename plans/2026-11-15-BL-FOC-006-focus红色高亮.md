# BL-FOC-006 focus 产品终端红色高亮

## 目标

终端打印 `[+] Product` 行时，指纹段内 `[*` 前缀 token（重点关注产品，如 `[*若依-RuoYi]`）整体红色，其余 token 颜色不变；性能零影响（着色在 SaveLog 打印 goroutine，无 focus 行仅多一次 Contains）。

## 当前状态

- 立项批准（用户 2026-11-15 确认 P1 + 立即实现），独立审查 REVISE 三条已并入 item。
- 输出链路事实：Product 行第 4 段（`strings.Join(slice[3:], "\t")`）为逗号分隔指纹 token；现有白/青按行交替（log.go:80-101）。

## 执行计划

1. common/log.go：SaveLog 顶部加 redStyle；Product 两个分支的第 4 段输出改走 `printFpsTail(fps, baseStyle, redStyle)`
2. printFpsTail：`Contains(fps, "[*")` 门控——未命中走原 `baseStyle.Println`（逐字节等价）；命中按 `, ` 分 token，`[*` 前缀 redStyle.Print、其余 baseStyle.Print，行尾 `fmt.Fprintln(color.Output)`
3. 新建 common/log_test.go：重定向 `color.Output` + `color.NoColor=false` 断言 ANSI 字节流
4. build + 定向测试
5. 同步五件套（backlog/控制台/CHANGELOG/模块文档/设计总览）+ check-sync 收尾

## 风险

- Windows 老 conhost：fatih/color 经 colorable 翻译 ANSI→WinAPI，逐段 Print 全走 color.Output，翻译路径不变（现有代码已同模式）
- 3 段 DC banner 行：切片语义 `Join(slice[3:], "\t")` 得空串，Contains 不命中走原路径（审查修订①约束）
- go test 非 TTY：库自动 NoColor=true 剥码，测试须显式置 false（审查修订②）

## 验证方式

- 单测：无 focus 段输出逐字节等于 `baseStyle.Sprint(fps)+"\n"`；有 focus 段红码精确包裹 `[*token]` 且仅此一处
- `go build ./...` + `go test ./common/`
- 落盘文件/JSON 无 ANSI（WriteFile 消费原始串，代码路径不经过渲染函数——grep 佐证）
- 真机：用户实测红色 `[*产品名]`，`-nocolor` 与文件输出纯文本

## 决策记录

- 打印层着色（否决数据层嵌 ANSI：污染落盘文件；否决结构化渲染重构：改动面大零增量收益）
- FgRed 无 Bold（与 `[+]` 漏洞行红色同语义同规格）
