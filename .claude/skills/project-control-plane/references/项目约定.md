# 项目约定（实例数据与格式契约）

backlog/文档体系的格式与状态取值。**本文件是唯一权威**——状态值、编号规则不得在其他文件重复定义。加载上下文包或生成/核对 backlog 时读取。

**按场景读节**（不必全读）：
- 生成/核对 backlog item → 「模块与 backlog 编号」+「状态与优先级」+「Backlog item 格式」（含方案节分级要求）
- 写/审 控制台、总览、模块文档、backlog 索引 → 「文档结构」+「语言规范」+「控制台与索引行规则」
- 路由判断/编号问题 → 「模块与 backlog 编号」
- 上下文包加载 → 「上下文包（按需加载，不默认读全项目）」
- 外部状态授权 → 「环境与外部状态」

## 文档结构（四层金字塔，渐进式披露）

```text
第0层  docs/项目控制台.md          ← 唯一人类入口（目标 ≤60 行，>150 行 check-sync 报警）：
                                        一句话定位 + 当前阶段 + 活跃 item（未完成/进行中/待验收）
                                        + blockers + 推荐下一步（仅未完成项）
第1层  docs/设计总览.md            ← 现系统架构图 + 模块能力地图（每模块 3-5 行）+ 活的设计决策
      docs/当前实现总览.md         ← 现系统代码能力地图
第2层  docs/modules/<NN>-<模块>模块.md   ← 模块文档：定位 → 关键决策(为什么) → 架构数据流
                                            → 关键功能怎么做 → 机制/表设计
      docs/backlog/<NN>-<模块>.md       ← 模块索引：演进叙事(2-3 句) + 状态汇总 + item 表
第3层  docs/backlog/<NN>-<模块>/BL-<MODULE>-<NNN>.md   ← item：方案节(人话) + 范围/验收
                                                            + 状态记录(证据)
      plans/<date>-<backlog-id>-<task-name>.md   ← 执行记录
冻结层 docs/archive/               ← 历史文档（接手审计、废弃系统分析），注明冻结日期，只增不改
      docs/CHANGELOG.md            ← 全部改动（带 `## YYYY-MM-DD` 日期标题）
```

**分层规则**：

- **上层只存摘要 + 链接，禁止把下层细节拉上来**（单行 ≤200 字符，适用控制台与总览全部段落，见「控制台与索引行规则」）。
- **闭合即归档**：item 验收闭合后当次从控制台删除——信息已活在模块索引 + CHANGELOG 两处，控制台不留划线残迹（check-sync 监测）。
- **agent 任务加载包封顶四样**：控制台头部 + 设计总览中该模块的能力地图行 + 该 item + 关联模块文档。不读同模块其他 item（方案节引用需深挖时例外）。
- backlog 两种形态：① 单文件 `<NN>-<模块>.md`（item 少时，item 正文直接写在模块文件内）② 拆目录 + per-item 文件（item 多时，模块文件降级为索引+状态汇总，item 正文各占一文件，标题用 `# BL-…`）。单文件超 500 行触发拆分（check-sync.py 监测）。
- 模块索引头部必须有**演进叙事**：2-3 句讲清该模块经历几轮演进、每轮解决什么问题，让 N 行平铺有脉络可读。
- **存量不追溯**：模块文档「关键功能怎么做」节与索引「演进叙事」——新模块/新索引必建；存量欠账已于 2026-10-22 清零：专项批次补 6 份模块文档 + 6 份索引，连同此前已有的 04/07 模块文档与 06/08 索引，8 模块文档与 8 索引现全覆盖。

## 语言规范（分层风格 + 四禁令）

文档两种风格，按层适用（对齐 CLAUDE.md 原则 13：决策场合叙事优先，审计场合证据优先）：

| 位置 | 风格 | 面向 |
|------|------|------|
| 第0-2层 + item 方案节 | 叙事：结论一句话先行、例子贯穿、术语首现给白话 | 第一次读的人（批准时点的用户） |
| 第3层状态记录 / 验收条件 / CHANGELOG | 证据：可以密、带数据带 文件:行号 | 审计复查 |

**四禁令**（第0-2层与方案节执行，违反=返工）：

1. **禁止裸编号引用**——提其他 item 必须自带一句白话摘要：写"复用 BL-06-094 的合并机制（合并是单个数据库事务，合并前先存一份可回滚的快照）"，不写"094 全语义"。编号只是深挖入口，不是必读前置。
2. **术语首现必解释**——行话第一次出现给括号白话，如"水位线（记录上次处理到哪的标记）"、"墓碑行（打删除标记而非真删的行）"。
3. **禁止一次性黑话**——只在当次会话有意义的压缩（如"共表方案A"、"双条件捞人"）落文档时必须展开成人话。
4. **写完自查**——一个没跟过开发的读者，不跳转任何文件，能否看懂这段在说什么、为什么。答不上=重写。

### 控制台与索引行规则（7799 与 5463 字符两次教训）

`docs/项目控制台.md` 是唯一人类入口，**只存汇总，不存 item 详情**：

- **backlog 索引表**每行 = 模块名 + backlog 路径 + 状态汇总（"N item：X 已完成 / Y 进行中 / Z 未开始；M 已验收"），单行 ≤200 字符，**适用于控制台全部段落**（含"当前状态"与"推荐下一步"），不止索引表。item 详情回 per-item 文件。
- **推荐下一步只列未完成项**：已验收闭合的 item 从控制台**删除**——模块索引 + CHANGELOG 已有两份，控制台不留划线残迹（check-sync 报警）。
- **禁止索引行/段落退化**为 mini-backlog（把多 item 的根因/修复/验证细节塞进一行或一段）。
- **状态词唯一**：索引行/演进项的状态词必须与 backlog item 验收状态字段一致（check-sync 状态漂移检查）。

## 模块与 backlog 编号

- `00` 保留给总览/规则；`01+` 表示当前阶段模块顺序。
- `docs/modules/<NN>-<模块>模块.md` ↔ `docs/backlog/<NN>-<模块>.md`（或 `docs/backlog/<NN>-<模块>/`）必须成对同号。
- 新模块 = 取下一个号，模块文档 + backlog 同建。不改已有编号，除非用户明确批准重排。

当前编号（项目实例）：

```text
00: modules/00-集成与部署模块.md（无对应 backlog 索引——00 为集成/部署文档；backlog 规则唯一权威在本文件）
```

## 状态与优先级（唯一权威）

- **backlog 状态**：`未开始` / `进行中` / `已完成`。不得发明 blocked/deferred/canceled/reviewing——阻塞项保持 `未开始`/`进行中`，原因记入状态记录或 blocker 节。
- **优先级**：P0 阻塞当前阶段主链路 / P1 重要但不阻塞 / P2 体验·质量·工程优化 / P3 远期增强。
- **验收状态**（与 backlog 状态分离）：`未验收` / `待验收` / `已验收` / `验收未通过`。
  - `已完成` = 实现 + 本地验证完成；`已验收` = 通过阶段级验收证据。不因代码存在而验收。
  - 验收失败 → backlog 状态按实现现实，验收状态记 `验收未通过` + 失败证据；未跑验收用 `未验收`/`待验收`。
- **blocker 分类**：`待产品决策` / `待技术方案` / `待外部依赖` / `待验证`。项目级 blocker → 控制台；item 级 → item 状态记录。

### 伪完成判定（本次实践沉淀——5 处伪"已验收"教训）

`验收状态：已验收` 必须同时满足三条件，任一不满足即伪完成，改回 `待验收`/`未验收`：

1. **验收条件全勾**：`### 验收条件` 下所有 `- [ ]` 已勾成 `- [x]`；若有真机实测项，必须有"用户实测通过"记录。
2. **状态记录闭合**：状态记录末条含"用户真机实测通过"/"验收通过"或等价证据，不能停留在"待用户实测"。
3. **backlog 状态一致**：`状态：未开始` 的 item 验收状态不得为 `已验收`（未开始不能已验收）；`状态：已完成` 才可能 `已验收`。

**反向规则**：禁止用 `已完成` + `已验收` 掩盖"待用户实测"——若验收条件真机项未勾，状态记 `待验收`，控制台同步 `待验收`，等用户实测后再置 `已验收` 并补闭合记录。

**字段滞后（反向伪完成，8 处实证）**：状态记录已有"用户验收通过 / item 闭合"证据，但 `验收状态` 字段仍停 `未验收`/`待验收`、验收复选框未勾——同属名实不符。核对状态记录末条证据：一致则升级字段并勾选复选框。闭合 item 从控制台删除后，**索引表行是状态漂移的唯一机械哨位**（check-sync 检查 9），状态变化必须当次同步索引行。

### 关联字段有效性（本次实践沉淀——6 项孤儿引用教训）

`关联计划`/`关联代码`/`关联模块文档` 字段值必须满足：

- **路径必须存在**：写出的路径在仓库中能找到；不存在则改指存在的文件，或显式写 `—` + 注记原因（"item 已完成，计划未建，细节见状态记录"）。
- **禁止"待建"残留**：标"（待建）xxx"或"（实现前补建）xxx"的路径，item 完成后必须补建文件或改字段为 `—`，不得长期留"待建"占位（check-sync 会报 HIGH 孤儿引用）。
- **ID 正确**：`plans/<date>-<id>-...` 的 id 必须与 item ID 一致（曾发生 BL-03-008 误编 bl-09-013）。
- **关联模块文档归属**：跨模块 item 关联多个模块文档时，每个路径都必须存在；若某模块未独立建模块文档，改指实际存在的模块文档（如 10 前端复刻归 04 Web 面板模块）。

## Backlog item 格式

```md
## BL-<MODULE>-<NNN> <标题>

（per-item 文件中标题用 `#` 一级标题，模块单文件形态用 `##` 二级标题）

- 模块：<模块名>
- 优先级：P0
- 状态：未开始
- 当前阶段：阶段一
- 价值：<一句话价值>
- 关联模块文档：docs/modules/<NN>-<模块>模块.md
- 关联计划：
- 关联代码：
- 验收状态：未验收

### 方案（立项时必填——人类批准的检查点，写给审批者，不写给实现者）

- **做什么**：<一句话>
- **为什么**：<触发与价值，含触发案例>
- **怎么做**：<方案要点，人话叙事；引用其他 item 的机制必须带自包含白话摘要（见「语言规范」禁令 1）>
- **为什么这么做**：<关键取舍；否决过什么备选、为什么>

### 范围
- ...

### 不做
- ...

### 验收条件
- [ ] <可测条件>
- [ ] <可测条件>

### 依赖
- ...

### 状态记录
- YYYY-MM-DD：<状态变更/意外发现/blocker 原因>
```

**方案节分级要求**：

- **立项时点 = B0/B 产出 item 草稿时**——用户确认优先级即批准方案（这是人类检查点），草稿必须已含方案节。
- **D/H 四要素**（做什么/为什么/怎么做/为什么这么做）；**D-lite 可降级**：一行方案 + 一行理由（可与`价值`字段合并写）。
- Mode D / D-lite / H 进入实现时核对方案节，缺则先补齐再动代码（兜底，不应发生）。
- **D-mini**：无 item，不适用。
- 存量 item 不追溯补写；新立项起执行。
