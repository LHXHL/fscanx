# 查询验收协议：Mode A / R / F

进入前已完成路由（SKILL.md）。状态值与验收状态定义见 `项目约定.md`。

**按 Mode 读节**（文件 39 行，三 Mode 互斥各 11 行，只读当前模式）：
- 状态评审 → Mode A
- 只读审计 → Mode R
- 阶段验收 → Mode F（含独立审计 + 契约一致性核查）

## Mode A：状态评审

触发："现在项目到哪了 / 下一步做什么 / 阶段状态 / 哪些 Backlog 没完成"。

1. 读控制台 + backlog 摘要（存在则读）。先跑 `python .claude/skills/project-control-plane/scripts/check-sync.py` 快速定位状态漂移/孤儿引用/体积超标，作为评审基线。
2. 提炼：阶段目标 / 活跃 item / blockers / 近期完成 / 推荐下一步。
3. 推荐项若模糊（见模糊检测）→ 标注："推荐 {item}，但范围较模糊，建议先走 Mode B0 或 Mode H"。
4. 回复三件套 + top 1–3 风险。
5. 🛑 不实现，除非用户明示。

成功：用户不读全文档也能懂状态；推荐点名具体 backlog ID（或说明控制面文件缺失）；模糊项已标注。

## Mode R：只读审计

触发："检查最近提交 / 按设计·plan·backlog 核对最近实现 / 排查遗漏、回归、测试滞后、文档残留 / 只出报告不改代码"。

1. 先确认范围：近 N 天、选定模块/plan、是否含当前未提交工作区改动。
2. 最小上下文：控制台 + 相关 plans + 相关 backlog + 相关模块文档 + 近期改动文件 + 相关测试。
3. 按设计/plan/backlog/声明范围核对代码、测试、文档一致性。**伪完成专项**：逐 item 核对 `验收状态：已验收` 三条件（验收条件全勾 + 状态记录闭合 + backlog 状态非"未开始"），不满足归为 `文档与代码不一致`（高/中等级，位置指 backlog item 文件）。
4. 每条发现唯一归类：`已确认代码问题` / `测试滞后·夹具过期` / `文档与代码不一致` / `风险点但证据不足`；并含：等级（高/中/低）+ 位置（file:line 或文档节）+ 现象 + 影响场景 + 建议；明确区分已提交改动 vs 未提交工作区。
5. 出报告即停；用户要求继续时，先归并修复队列（P0 正确性 / P1 测试文档一致性 / P2 清理）再进 D/D-lite。

成功：报告可直接当修复队列用；已提交与未提交问题分离。

## Mode F：阶段验收

触发："阶段完成了吗 / 验收检查"。

1. 读阶段范围 + 全部内含 item + 各验收条件。
2. **独立审计**：先跑 `python .claude/skills/project-control-plane/scripts/check-sync.py` 暴露文档状态漂移/孤儿引用，再 spawn `general-purpose` agent 重载各 item、验收标准与声称证据，判定：证据是否具体（测试输出/diff/API 响应 vs 空话）？有无 `已完成` 项缺证据？有无契约不一致（OpenAPI vs 路由、迁移 vs 模型、模块文档 vs 行为）？**伪完成专项**：逐 item 核对 `验收状态：已验收` 是否满足三条件（验收条件全勾 + 状态记录闭合 + backlog 状态非"未开始"，见 `项目约定.md`「伪完成判定」），不满足则降级 `待验收`/`未验收` 并记证据缺口。≤2 轮补证。
3. 契约一致性核查（相关时）：OpenAPI↔后端路由 / DB 文档↔迁移与模型 / 模块文档「关键功能怎么做」节↔实现实际行为 / 设计总览能力地图↔实际模块与能力 / 控制台计数↔backlog 实算（check-sync 已含，复核其输出）。
4. 按唯一权威状态值归类；验收状态按证据：`已验收` / `验收未通过`（附失败证据）/ `待验收` / `未验收`。
5. 出阶段验收汇总 + 收官或继续的建议。

成功：无"看着没问题"；每阶段目标有证据或具名缺口；延期工作仍留在 backlog。
